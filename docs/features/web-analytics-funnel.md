## Design and acceptance criteria

1. Reuse gtag and proxy; initialize once per page (including duplicate module evaluation), disable automatic pageview, send only allowlisted virtual routes. Strip query/hash/path from landing/referrer context; keep referrer origin. Development/test/preview must not load production GA. An explicit separate test measurement ID enables DebugView only in development.
2. Keep old event names for equivalent transitions. Import starts when a real File is accepted (not picker opening), succeeds once on usable metadata. Generate starts when processing is invoked and succeeds after a nonempty PNG is produced. Export request is the action; dispatch means handed to browser download/share, never disk persistence. Instrument actual share handoff separately from promise cancellation/error.
3. A small in-memory task lifecycle deduplicates metadata and terminal task outcomes. No task ID, user ID, content, names, file URLs, raw errors or arbitrary strings. Bounded format/size/duration/resolution, bounded processing milliseconds, finite errors, package version and schema version only.
4. Explicit clear/replacement/reset is cancellation if the task has not already finished. Picker cancellation creates no accepted-file task. Unknown unfinished work (tab close/crash, metadata never returns, etc.) remains unknown; do not infer cancellation or success from unload. Task summaries count first dispatch once even if export is repeated.
5. Tests use local event spies/module stubs; real GA DebugView is a separate pending owner check. Existing unit suite and smoke suite first, then targeted unit/lifecycle interaction tests, lint, typecheck and build. No production GA test data.

## Event contract and trigger locations (schema 2)

The requested semantic names map to existing wire events as follows. Do **not** create GA derived duplicate events with canonical names or sum both names. All business events and manual pageviews carry `platform=web`, `app_version` from package.json (currently 0.1.0), and `analytics_schema=2`. Use the schema filter and rollout date to separate historical definitions.

| Requested meaning          | Wire event             | Real trigger / location                                                                                                                                              |
| -------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------- |
| import_start               | `upload_started`       | `App.handleVideoSelect` creates `AnalyticsTask` after an accepted File from picker/drop. Opening/cancelling a picker is outside this task denominator.               |
| import_success             | `upload_completed`     | Hidden video `loadedmetadata` callback with finite positive duration and dimensions; once per task, not selection or preview URL creation.                           |
| generate_start             | `processing_started`   | `App.handleStartProcessing` before invoking the processing pipeline; concurrent duplicate invocation is guarded.                                                     |
| generate_success           | `processing_completed` | Pipeline promise resolves and canvas produces a nonempty PNG; no success on rejection or empty output.                                                               |
| export_request             | `export_started`       | `App.handleDownload` / `App.handleShare`, with `export_method=download                                                                                               | share`. |
| export_dispatch            | `export_completed`     | Download: anchor `click()` returns. Share: `shareGeneratedImage` promise resolves. Neither proves disk persistence, target-app delivery or a human using the result. |
| task_error (generate)      | `processing_failed`    | Generation catch, unavailable element resources or empty PNG; `task_stage=generate`. Retained legacy event, no additional `task_error`.                              |
| task_error (import/export) | `task_error`           | Metadata error/invalid metadata; download/share rejection. Exports can retry.                                                                                        |
| explicit cancellation      | `task_cancelled`       | Clear, replacement or reset; `cancel_reason=clear                                                                                                                    | replace | reset`. Share `AbortError`uses`share_cancelled` and leaves task open for retry. No string matching on exceptions. |
| terminal task outcome      | `task_finished`        | At most once per accepted-file task: `task_outcome=dispatched                                                                                                        | error   | cancelled`; generation/import errors end the task, export errors/cancelled shares do not.                         |

`AnalyticsTask` holds only in-memory lifecycle state and deduplicates import success, generation transitions and terminal summaries. Repeated export actions intentionally each have request/dispatch events, but only the first dispatch finishes a task. A reset after dispatch does not emit cancellation. A callback that never arrives does not produce a synthetic terminal event. Late metadata after generation is ignored. Existing `preview_shown` and bounded feedback events remain supplemental, not funnel completion steps. Native Capacitor-origin tracking is disabled by the Web origin gate; no native analytics implementation is added.

Parameter allowlist in `analytics-events.ts`:

- `upload_source`: picker/drop (native labels retained for compatibility but Web tasks do not use them).
- `video_extension`: mp4/mov/webm/m4v/avi/mkv/other. `video_mime` has the corresponding six finite MIME values plus other. These classify containers, not actual codec support.
- `video_size_mb_bucket`: ≤10/25/50/100/250/500 or >500 MiB. `video_duration_bucket`: ≤10/30/60/120/300 or >300 seconds. `video_resolution_bucket`: short-edge ≤480/720/1080/1440/2160 or >2160; invalid metadata = unknown. Wire labels use `<=` and `>`.
- `processing_time_ms`, `stage_time_ms`: rounded nonnegative finite milliseconds, capped at one hour; use as numeric custom metrics only if needed, never dimensions.
- `error_code`: metadata_unreadable / processing_failed / empty_output / export_failed / resources_unavailable. No original exception text, filename, content, OCR, file URL or arbitrary MIME suffix is sent. Error text still shown/logged locally by the pre-existing UI is not sent through analytics.
- Runtime transport rejects unknown event names, unknown parameter keys and arbitrary strings, including attempts to override context/version/platform. No `task_id`, user identity or cross-session task persistence.

## Measurement definitions

**GA4 user funnel:** Explore → Funnel exploration, closed funnel, indirectly followed by (other events may intervene), steps `upload_started` → `upload_completed` → `processing_started` → `processing_completed` → `export_started` → `export_completed`. Filter `platform=web`, `analytics_schema=2`, deployed Web stream/hostname. Start with a 30-minute step limit and document it; inspect slower tasks separately before treating drop-off as abandonment. Break down device category, browser, then session source/medium separately. This measures users completing an ordered event sequence; one user can have several tasks, and steps can span different tasks. It is **not** a task join or task success rate. A supplemental `page_view` → `upload_started` funnel measures visitor-to-accepted-file conversion.

**Task outcomes:** Each accepted file starts one task (`upload_started`); `task_finished` gives at most one known outcome. In a sufficiently long, stable reporting window, count `task_finished` by `task_outcome` to compare dispatched/error/explicit cancellation. The completed-task dispatch rate is `dispatched / (dispatched + error + cancelled)`; it excludes unknown unfinished tasks and can overstate all-attempt completion. Show the started count and unclosed gap alongside it. `dispatched / upload_started` and generation success/start counts are **window-level approximations**, not exact cohort rates: task completion can cross date boundaries, events can be blocked/lost, and schema/consent changes affect counts. A negative unclosed gap signals boundary/transport issues, not negative unfinished tasks. Without IDs/persistence this implementation cannot reconstruct exact task cohorts across windows; do not claim otherwise. Do not use repeated `export_completed / upload_started` as task success. There is no disk-save success metric.

Picker dismissal creates no accepted-file task; explicit clear/replacement/reset is measured cancellation; leaving a tab, crashing, OpenCV loading indefinitely, or waiting for metadata without a callback is unknown unfinished. No unload/beforeunload success/error/cancellation is synthesized. Initial OpenCV load failures remain local console errors and may leave accepted-file tasks unknown before generation; they are not relabelled as user cancellation.

### Final audit correction: processing completion contract

The existing `processVideo` catches exceptions internally and returns normally on several no-output paths; a default/stale canvas could therefore be reported as generation success. To make state callbacks reliable, this change also returns a finite explicit result (`success`, `empty_output`, `processing_failed`) from processing orchestration, without changing frame selection/stitching algorithms. `App` clears the output canvas before each attempt and requires `success` plus a nonempty PNG. Tests add real-pipeline failure/no-output regression coverage and update the existing UI processing stub to honor the result contract. Metadata that arrives while the pipeline waits is still a real import success; its latency uses the original import start clock.
